Plain text

The functions behind jldocs; see For AI agents.

DocBrowser.lookup — Function
DocBrowser.lookup(query; outline=false, section=0, brief=false, width=100, context=Main, load=false) -> String

The page that the browser shows for query, as plain text. query is a name such as Base.sort! or Plots.plot, a place in a manual such as manual/arrays#Broadcasting, stdlib/Random or the path of a Markdown file, or anything that docs: takes at the help?> prompt.

Links in the text end in a number, as in sort[3], and the list at the end gives what each links to, in a form that lookup takes. With outline, only the headings of the page are listed, numbered; section gives the text under one of them. With brief, only the start of each docstring is given: its signature and first paragraph.

A package of the active project that a name is asked for in, such as Plots for Plots.plot, is loaded first, which runs its code, so that its docstrings can be read. If it would have to be precompiled first, it is only loaded with load, and until then its page shows what its source documents, such as its README. load also loads the other packages of the project when query is not found without them.

DocBrowser.find_docs — Function
DocBrowser.find_docs(query; text=false, internal=false, limit=20, load=false) -> String

Names, and sections of Julia's manual and of the manuals of the project's packages, that match query, best first, one a line, each in a form that lookup takes, and for a section of a manual, its file. With text, the words are looked for in docstrings and in the text of the manuals too, not only in names and headings; that is done anyway when nothing else matches.

The names of packages that are not loaded are not known until they are, which load does, running their code. Their manuals are searched either way.

DocBrowser.list_names — Function
DocBrowser.list_names(mod; internal=false, load=false) -> String

The names of module mod (a module, or its name), by kind. Each says whether it is exported or public, which package it comes from when it is re-exported, and whether it is documented.

Package manuals

DocBrowser.fetch_package_docs — Function
DocBrowser.fetch_package_docs(pkg) -> String

Download the manual of package pkg (a module, or the name of a package of the active project) when it is not installed with the package, as when the package is in a subdirectory of a repository whose manual is elsewhere in it, like GLMakie's in Makie.jl. The manual is taken from the release of the installed version: the tag or commit at which the package's directory has the tree hash of the installed one. Returns where it is kept. Only GitHub repositories are supported; a GITHUB_TOKEN in the environment raises GitHub's limit on requests.

The browser does this by itself, in the background, for the packages it shows that need it, unless the environment variable JULIA_DOCBROWSER_AUTODOWNLOAD is no.

DocBrowser.explain_docs — Function
DocBrowser.explain_docs(pkg; online=false, io=stdout)

Say where the browser looked for the documentation of package pkg (a module, or the name of a package of the active project), what it found, and why it did not find more: the manual in the package's source, its list of pages, a downloaded manual, the [docs] section of its project file, its repository, and the link to its hosted documentation. With online, it also looks for the release of the installed version in the repository, as downloading the manual does. For package authors, it says what would let the browser find more.
